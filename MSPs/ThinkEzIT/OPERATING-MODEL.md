# ThinkEzIT POC Operating Model

## Mission

Within 90 days, produce measurable operational adoption inside ThinkEzIT and commercial evidence for a sellable managed-AI offering.

## North-star outcomes

### Adoption

ThinkEzIT staff use the delivered workflow/agent capability in real operating work.

Evidence examples:
- completed production workflow runs
- repeat usage by staff
- reduced manual touchpoints
- reduced cycle time
- fewer missed fields / rework events
- staff request to retain or expand the capability

### Sellability

ThinkEzIT can explain, scope, quote, and deliver the managed-AI offer without depending on an improvised MJC-only process.

Evidence examples:
- approved offer definition
- repeatable discovery and qualification process
- pricing logic and delivery boundaries
- customer-facing material
- defined onboarding and support model
- governance/security evidence package

### Revenue

The POC must pursue actual market proof inside the 90-day window.

Strongest evidence:
1. Collected revenue
2. Signed agreement / paid pilot
3. Approved purchase commitment
4. Qualified proposal under active buyer review
5. Documented qualified pipeline

Pipeline alone is not equivalent to revenue and must not be reported as such.

## Workstream sequence

### 1. Automate ThinkEzIT operations

Start with workflows that staff already perform. Do not invent AI work merely to demonstrate AI.

Initial reference workflow:
`onsite evaluation -> structured capture -> validation -> quote-ready output -> downstream customer workflow`

### 2. Establish ThinkEzIT's AI-enabled MSP operating model

Turn successful automation into a usable operating system for the team: repeatable prompts/workflows, source controls, approvals, documentation, customer handling, security boundaries, and measurable operating metrics.

### 3. Productize managed AI

Convert validated internal capability plus MJC governance/security expertise into a managed service ThinkEzIT can sell and support.

## Phase gates

### Gate A — Workflow proof

Pass when a real ThinkEzIT user completes the target workflow successfully and the result is accepted for real operational use.

### Gate B — Repeated adoption

Pass when the workflow is used repeatedly without MJC manually rescuing routine execution.

### Gate C — Offer readiness

Pass when ThinkEzIT can present and scope the managed-AI service from documented material and delivery runbooks.

### Gate D — Market validation

Pass when a qualified external prospect engages materially with the offer.

### Gate E — Revenue proof

Pass when the offer produces collected revenue or another explicit paid commercial commitment within the 90-day objective window.

## Reporting discipline

Every status report must distinguish:
- built
- tested
- accepted
- used
- repeated
- proposed
- sold
- paid

Never collapse these states into a generic `done` label.
